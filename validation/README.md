# Real-world validation harness

Everything in `fixtures/` is synthetic and generated by `scripts/build-fixtures.mjs`.
Those fixtures prove the checker does what it was written to do. They cannot
prove that a `broken` finding corresponds to a map that renders wrong, because
the same process authored both the check and the thing it checks.

This harness runs the built CLI against production styles served by real tile
providers that nobody here controls. Every finding it produces is one of two
things:

- a real contract break shipping in production, or
- a false positive in the checker.

Separating those is the point. A validator that cries wolf on a working map gets
uninstalled the same afternoon, so the false-positive rate is the number that
decides whether this product is viable.

## Running it

```bash
npm run build          # the harness runs the built CLI, not the sources
npm run validate:real
```

Options: `--only <target-id>`, `--refresh` (re-fetch cached styles),
`--offline`, `--timeout-ms <n>`.

Reports land in `validation/reports/` and cached styles in `validation/.cache/`.
Both are gitignored — they are third-party content that changes without notice,
and committing them would turn provider-side edits into repo diffs.

## Deliberately not a CI gate

`validate:real` always exits 0 unless the harness itself broke. It is not part of
`npm run check`, for two reasons:

1. It depends on third-party uptime. A provider outage is not a regression here.
2. Until the false-positive rate is near zero, a red gate would only teach
   everyone to ignore it.

It becomes a gate after the findings in `FINDINGS.md` are resolved and the
corpus produces a stable, explained baseline.

## Corpus

`corpus.json` lists the targets. It spans three tile schemas (OpenMapTiles,
Shortbread, MapLibre's demo schema) and four independent providers, because
checker assumptions tend to hold for exactly the one schema they were written
against. `gaps` in that file records what is not covered yet — PMTiles and
MBTiles both still need real targets.

## Seeded failures

The documented release gate is "seeded prototype catches at least 8 of 10
intentional contract failures" (see the Validation section of the documentation
site in `site/`). `validation/seed.mjs` measures it:

```bash
npm run validate:seed                                # openfreemap-liberty
npm run validate:seed -- --target versatiles-colorful
```

It seeds ten known contract breaks into a cached corpus style, one per check the
product claims to perform, and counts what the checker notices.

Two rules keep the number honest:

- **Detection is a diff against the unmutated baseline.** A style that already
  has findings would otherwise score full marks for noticing nothing.
- **A mutation that cannot be expressed against a style is excluded from the
  denominator and named in the output.** Padding the rate with breaks that were
  never introduced would be worse than a low score.

A mutation targeting a specific check asserts which check caught it. Without
that, the data-driven icon seed scored a pass off the static icon check.

Unlike `validate:real`, this one exits on its verdict — a gate that printed
`NOT MET` and exited 0 either way was not a gate:

| Exit | Verdict              | Meaning                                                        |
| ---- | -------------------- | -------------------------------------------------------------- |
| 0    | MET                  | 8 or more of the applicable mutations were caught.               |
| 1    | NOT MET              | The checker missed too many. A detection regression.             |
| 3    | CANNOT BE EVALUATED  | Fewer than 8 mutations are expressible against this style.       |
| 2    | —                    | Prerequisite missing: no built CLI, or no cached style.          |

Exit 3 is deliberately not folded into exit 1. Nothing was proven about
detection, which is not the same answer as "the checker missed too many", and a
caller choosing to tolerate it should not have to tolerate a real regression too.

Results are in `FINDINGS.md`.
